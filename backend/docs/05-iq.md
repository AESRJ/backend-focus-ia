# Test IQ con auto-ajuste de preferencias

## Qué es

Endpoint para guardar el resultado del test IQ (30 preguntas: matrices visuales,
series y razonamiento verbal). A diferencia del de TDAH, este endpoint además
**ajusta automáticamente las preferencias del usuario** según el resultado.

## Tabla de mapeo

| % aciertos | Nivel       | Modo (alias) | Duración |
|------------|-------------|--------------|----------|
| < 40 %     | Bajo        | absoluta     | 25 min   |
| 40–70 %    | Promedio    | alerta       | 35 min   |
| > 70 %     | Alto        | tranquilo    | 50 min   |

Lógica: puntaje bajo → necesita más restricción para concentrarse. Puntaje alto
→ ya autorregula bien, modo más permisivo.

## Anti-trampa: score se recalcula en backend

El frontend envía cada respuesta con un flag `isCorrect`, pero el backend lo
ignora y recalcula contra una tabla autoritativa (`CORRECT_INDEX`):

```python
CORRECT_INDEX = {
    1: 2, 2: 2, 3: 1, 4: 2, 5: 0, 6: 2, 7: 2, 8: 1, 9: 3, 10: 0,
    11: 1, 12: 1, 13: 2, ...  # 30 entradas
}

score = 0
for a in payload.answers:
    is_correct = CORRECT_INDEX.get(a.questionId) == a.selectedIndex
    if is_correct:
        score += 1
```

Así no importa si el cliente manipula `isCorrect`.

## Storage

En `User.profile_data["iq"]`:

```json
{
  "iq": {
    "score": 22,
    "total_questions": 30,
    "percentage": 73.33,
    "nivel_interpretacion": "Alto",
    "mode_recomendado": "tranquilo",
    "duracion_recomendada": 50,
    "total_time_ms": 312000,
    "completado_en": "2026-05-06T14:30:00Z",
    "answers": [...]
  }
}
```

## Lo que hace POST /iq/resultados (en una sola transacción)

1. Recalcula score con `CORRECT_INDEX`.
2. Mapea score a nivel + modo + duración con `_interpretar(score)`.
3. Guarda el resultado en `profile_data["iq"]`.
4. Actualiza `profile_data["mode_alias"]` y `profile_data["duration"]`.
5. Actualiza `PerfilEstudiante.nivel_restriccion` (fuente de verdad).
6. Si hay sesión activa, sincroniza su snapshot.
7. Commit único.

Todo en la misma transacción para que si algo falla, no quede un estado
inconsistente entre `profile_data` y `PerfilEstudiante`.

## Endpoints

- `POST /iq/resultados` body `{ answers: [...], totalTimeMs, completedAt }`
- `GET /iq/resultados` → último resultado o `null`.

## Validación

```python
class IqAnswerIn(BaseModel):
    questionId: int = Field(..., ge=1, le=TOTAL_QUESTIONS)
    selectedIndex: int = Field(..., ge=0, le=3)
    isCorrect: Optional[bool] = None  # ignorado
    timeSpentMs: int = Field(..., ge=0)

class IqResultadoIn(BaseModel):
    answers: List[IqAnswerIn]
    totalTimeMs: int = Field(..., ge=0)
    completedAt: Optional[str] = None
```
